1. PURPOSE
----------
This Software Test Plan (STP) describes the automated tests executed against
Stonewake. It covers UI end-to-end flows, API contract/behavior checks, and an
opt-in black-box security suite.


2. SCOPE
--------
IN SCOPE
  - UI authentication, navigation, and domain workflows (Deal Book, Countries,
    Institutions, Portfolio, Screenings, Monitoring, Company, Tenders, Settings)
  - API health, auth, portfolio, entities, countries, search, deals, screenings,
    company/ownership, monitoring, tenders, alerts, and document downloads
  - Security probes: SQLi, XSS, security headers, authz/malformed credentials,
    CSRF/session hardening

OUT OF SCOPE
  - MCP / Connected assistants
  - Manual exploratory testing
  - Performance / load testing
  - Visual regression baselines


3. TEST ENVIRONMENT & PREREQUISITES
-----------------------------------
Config (YAML, loaded by scripts/load-config):
  - config/default.yaml          env=local, suite=all, type=all, chromium,
                                 timeoutMs=30000, workers=2
  - config/env/local.yaml        headed=false, workers=2
  - config/env/ci.yaml           headed=false, workers=2, retries=1
  - config/suites.yaml           tag filters for smoke / regression / ui / api /
                                 security

Environment variables (typically via .env):
  - STONEWAKE_APP_URL            UI base URL
  - STONEWAKE_API_URL            API base URL
  - STONEWAKE_EMAIL              Login email
  - STONEWAKE_PASSWORD           Login password
  - API key in .env              Bearer auth for API tests; must allow report/pack
                                 downloads

Account requirements:
  - Analyst with Deal Book rights (tender dismiss / add-to-deal-book)
  - Admin rights (Settings API keys + audit log CSV export)

Browsers (UI projects):
  - Default: Chromium (Desktop Chrome)
  - Configurable via run config: firefox, webkit


4. HOW TESTS ARE RUN
--------------------
npm scripts (all route through scripts/run-tests.js):

  npm test                 Default run (UI + API; security excluded)
  npm run test:ui          UI only
  npm run test:api         API only
  npm run test:security    Security suite only (--type security --suite security)
  npm run test:smoke       @smoke tagged tests (UI + API)
  npm run test:regression  @smoke + @regression (UI + API)
  npm run test:ui:smoke    UI smoke
  npm run test:api:smoke   API smoke
  npm run test:headed      Headed browser
  npm run test:debug       Debug mode
  npm run test:ui:headed   UI headed
  npm run test:ci          CI profile (--env ci --type all)
  npm run report           Open HTML report

Playwright projects (playwright.config.ts):
  - ui-<browser>           testMatch: ui/*.spec.ts
  - api                    testMatch: api/*.spec.ts
  - security-api           testMatch: security/*.api.spec.ts
  - security-ui            testMatch: security/*.ui.spec.ts

NOTE: Security projects are NOT included in npm test, test:ci, smoke, or
regression. Run them explicitly with npm run test:security.


5. TAGGING CONVENTION
---------------------
  @ui          UI browser tests
  @api         API request tests
  @security    Security suite
  @smoke       Critical path / smoke
  @regression  Broader functional coverage

Suite tag filters (config/suites.yaml):
  all         no tag filter
  smoke       @smoke
  regression  @smoke + @regression
  ui          @ui
  api         @api
  security    @security


6. TEST LAYOUT
--------------
tests/
  ui/          Domain UI specs
  api/         Domain API specs
  security/    Opt-in security suite

src/
  constants/   env, routes, messages, test data, security payloads
  clients/     ApiClient
  pages/       Page objects
  fixtures/    Playwright test.extend
  security/    Shared security assertions

11. PASS / FAIL CRITERIA
================================================================================
PASS
  - All selected suite tests exit 0 under Playwright.
  - Assertions in each TC above are satisfied.
  - No unexpected 5xx or credential leakage in security assert helpers.

FAIL
  - Any assertion failure, timeout, or uncaught error in selected projects.
  - CI run (npm run test:ci) fails after configured retries (ci.yaml retries=1).


12. REPORTING & ARTIFACTS
-------------------------
  - Console: list reporter
  - HTML report: playwright-report/ (npm run report)
  - Traces: retain-on-failure
  - Screenshots: only-on-failure


13. ASSUMPTIONS & RISKS
-----------------------
  - Seeded / live environment data must include fixtures used by constants
    (country, company, institution, monitoring target, deal filters, etc.).
  - Tender and Settings UI tests mutate workspace state (dismiss/add match,
    create/revoke API key); account must have required roles.
  - Some document endpoints accept 200 or 404 where product may not yet expose
    every pack/deck for every entity.
  - Security suite is intentionally opt-in and may be noisy against rate limits
    or WAF behavior depending on environment.
